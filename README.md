# PDF Signer / Заявки ЖД

Отдельный локальный микро-проект экосистемы «Примени Аудит». Python CLI, без сетевых интеграций, OCR и растрирования исходного PDF. Основной источник требований: docs/requirements.txt.

Статус: локальный конвейер реализован и проверен на обоих предоставленных PDF. Полный Definition of Done ещё не выполнен: предоставленный PNG отличается от изображения в подписанном эталоне. Готовность к недельному пилоту не объявляется до согласования изображения и его размещения.

## Структура

```text
pdf-signer/
  signer.py                 локальная CLI и логика обработки
  config.example.json       компания, ИНН, геометрия, проверенный профиль
  config.local.json          локальная конфигурация, исключена из Git
  requirements.txt          зависимости конвейера
  requirements-dev.txt      зависимости тестов и визуальной проверки
  tests/test_signer.py       16 автоматических проверок
  docs/requirements.txt      исходные требования заказчика
  docs/REPORT.md             VERIFIED / UNKNOWN, результаты исследования
  docs/test-results.txt      полный результат тестов
  docs/verification.json     машинные подтверждения проверок
  private/                  исходники и факсимиле, исключены из Git
  output/final/             два результата PDF и журналы JSON/TXT
  output/negative/          результат проверки изменённого ИНН
  output/repeat/            результат повторной обработки
  tmp/                     вспомогательные материалы, исключены из Git
```

## Запуск на Windows / PowerShell

Обычный Python 3.12+:

```powershell
cd C:\malinkin\autosign\pdf-signer
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python signer.py "C:\Users\1\Downloads\Telegram Desktop\Заявка ЖД 03.10.pdf" --config config.local.json --output output/pilot-001
```

В этой сессии проверено на встроенном Python Codex. Можно использовать его без установки:

```powershell
$signerPython = "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"
& $signerPython -m unittest discover -s tests -v
& $signerPython signer.py "C:\Users\1\Downloads\Telegram Desktop\Заявка ЖД 03.10.pdf" --config config.local.json --output output/pilot-001
```

Каталог результата для нового запуска должен быть свободен от файлов с такими именами. Существующие результаты и исходник не перезаписываются. Код выхода: 0 — все страницы SIGNED/ALREADY_SIGNED; 2 — есть REVIEW_REQUIRED/ERROR; 1 — ошибка файла/конфигурации. REVIEW_REQUIRED и ERROR проверять по постраничному журналу.

Для нового компьютера скопировать config.example.json в config.local.json, положить клиентское факсимиле в private/facsimile.png. Реальные тесты требуют private/unsigned.pdf и private/reference.pdf; синтетические тесты используют системный Arial Windows. Факсимиле и PDF не включать в Git. Путь изображения разрешается относительно файла конфигурации.

## Правила конвейера

- ИНН и нормализованное название проверяются совместно в ограниченном блоке перевозчика. ИНН других участников не разрешает подпись.
- Координаты относительно подтверждённого заголовка «ПОДПИСИ СТОРОН». Проверяются подпись «Перевозчик», геометрия и допустимое положение блока.
- Размер страницы, CropBox, rotation, порядок и исходные потоки содержимого сохраняются. Изменение профиля даёт REVIEW_REQUIRED.
- Факсимиле добавляется как печатаемая PDF Stamp-аннотация. Это визуальный штамп, без криптографической электронной подписи. Клиентский файл изображения не изменяется; для белого фона применяется PDF color-key mask.
- ALREADY_SIGNED допускается только для точного проверенного appearance штампа в ожидаемом месте и с видимыми флагами. Неизвестные штампы, изображения, текст и графические отметки в области перевозчика требуют ручного рассмотрения. Белый фоновый прямоугольник эталона проверяется отдельно по конфигурации.
- Для SIGNED после сохранения проверяется наличие корректного appearance; PDF, не прошедший эту проверку, не публикуется как результат.
- На каждой странице своё решение. Ошибка страницы фиксируется как ERROR, изменения этой страницы откатываются, следующие страницы обрабатываются.
- Журнал JSON содержит номер страницы, заявки, дату, исходное/нормализованное название, найденный/ожидаемый ИНН, водителя, машину, метод, статус, причину и координаты добавленного штампа. Журнал TXT содержит краткий постраничный итог. Изображение и бинарные данные в журнал не записываются.

В этом MVP нет интерфейса ручного одобрения REVIEW_REQUIRED. Решение нельзя обходить изменением ожидаемого ИНН: конфигурация задаёт конкретного разрешённого перевозчика.

## Простой интерфейс для пользователя

Дважды нажмите «Запустить PDF Signer.cmd» в папке проекта. В окне нажмите «Выбрать PDF и подписать» и выберите исходный PDF. После обработки нажмите «Открыть готовый PDF» или «Открыть папку результата». Файл с суффиксом _SIGNED.pdf и журналы находятся в отдельной папке output/manual/<время запуска>. Ничего вводить в консоль пользователю не требуется.

Интерфейс: app.py (tkinter, входит в Python). Для разработки запуск: python app.py. На текущем компьютере launcher использует встроенный Python Codex. Проверены создание окна и полный путь интерфейса → обработка реального PDF → готовый результат с четырьмя подписанными страницами. Интерактивный выбор файла проверяется пользователем при первом запуске.
